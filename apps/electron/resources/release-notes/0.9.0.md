# v0.9.0 — Claude Agent SDK 运行时升级、飞书/ Lark 消息推送、Telegram 超级群话题

## 新功能

- **Claude Agent SDK 升级至原生二进制分发（0.2.123）** — SDK 0.2.113 将包拆分为精简核心（`@anthropic-ai/claude-agent-sdk`）加平台相关的可选依赖（携带原生 `claude` 二进制文件）。U Agents 现通过构建脚本别名 `@anthropic-ai/claude-agent-sdk-binary/claude` 解析二进制文件（开发模式下按架构回退到包），ripgrep 从已弃用的 SDK 捆绑版本迁移到顶层 `@vscode/ripgrep` 依赖。`electron-builder.yml` 现在将精简核心、二进制别名和 `@vscode/ripgrep` 作为 macOS、Linux、Windows 的 extraResources 捆绑；构建脚本在主机架构与目标架构不同时通过 `npm pack` 交叉获取目标架构的二进制包。每平台安装包体积增加约 210 MB——这是新 SDK 打包模型的内在变化。（`9ae87dc1`）

- **飞书/ Lark 消息适配器（第一阶段 + 第二阶段）** — 继 Telegram 和 WhatsApp 之后的第三个消息平台。通过开放平台连接飞书自建应用——`open.larksuite.com`（国际版）或 `open.feishu.cn`（国内版）——使用与 Telegram 相同的 `/pair` 流程，无需公网 Webhook URL（长连接 WebSocket 传输）。第一阶段覆盖**设置 → 消息 → 飞书/ Lark** 中的应用 ID + 应用密钥 + 区域选择器，支持私信文本收发、群聊 @ 提及和会话配对。第二阶段新增消息流式编辑（单条消息持续更新）、交互式卡片（计划接受/允许/拒绝按钮，schema 2.0，最多 10 个按钮，30 字符标签）、图片和文件双向附件，以及通过飞书 `post` 消息类型支持 Markdown 渲染（加粗/斜体/删除线/链接/代码块，纯文本回复仍使用轻量的 `text` 类型）。7 种支持的语言各新增 24 条 i18n 键值。关闭 (#583)，部分解决 (#639) 和 (#584)。（`5443aa41`，`e56862e4`）

- **Telegram 超级群配对及自动化话题路由** — 从**设置 → 消息 → Telegram → 配对超级群**配对 Telegram 超级群到工作区；机器人在任意话题中输入 `/pair <验证码>` 后捕获超级群的 `chat.id`。配对要求 `chat.type === 'supergroup'` 且 `is_forum === true`，因此私信、普通群和普通超级群不能注册为工作区超级群。已绑定的绑定显示为设置和 `list_messaging_channels` 中的 `群组 › 话题 #N`。在 `automations.json` 的任意自动化匹配器中添加可选的 `telegramTopic` 字段，生成的会话将绑定到该名称的话题（首次使用时创建，之后复用；共享同一值的话题共享一个话题）。话题值支持环境变量展开（如 `"Reports: $LABEL"`）。（`77e1f5f1`，`dd22996e`）

  ```json
  {
    "matcher": "^urgent$",
    "telegramTopic": "紧急警报",
    "actions": [
      { "type": "prompt", "prompt": "调查紧急问题：$LABEL" }
    ]
  }
  ```

- **全部会话视图中的未读分组模式** — 继按日期分组和按状态分组之后的第三种分组选项，将会话列表分为两个固定桶：**未读（N）**在上，**已读（N）**在下，各自按 `lastMessageAt` 排序。两个桶始终渲染，即使为空，以便当前模式始终可见；空组取消折叠箭头。该模式在状态子视图（收件箱、星标等）中禁用，因为状态筛选已约束列表——这些视图回退到按日期分组。折叠状态按模式独立保存，因此在未读模式中折叠已读组不会影响其他模式。（`59b826a2`）

- **Telegram 消息设置重构升级至正式版** — 设置 → 消息 → Telegram 卡片现在将绑定拆分为直接会话行（私信配对）和超级群部分（配对时为可折叠大箭头，未配对时显示"配对超级群"操作按钮），效仿 AI 设置中的 `WorkspaceOverrideCard` 模式。话题绑定的绑定显示为 `标题 / # 话题名 · 话题 #N` 行。WhatsApp 和飞书卡片保持现有扁平布局——它们没有超级群/话题概念。（`312016a3`，`7e235f8e`）

## 改进

- **带重试控制的弹性会话消息加载** — 会话消息加载有两种故障模式导致用户盯着无限加载动画：元数据刷新后的过时 `loaded` 标志，以及丢失的传输回复。新的 `replaceLoadedSessionAtom` 执行权威的全会话更新，在一个事务中将会话标记为已加载并更新元数据，消除了之前 `updateSessionDirect + sessionMetaMapAtom.set` 发散风险。新的 `deriveSessionMessagesLoadState` 帮助函数区分内存就绪与过时已加载标志、已知为空与尚未加载、加载失败与仍在加载——`ChatDisplay` 用它来在传输抖动丢失加载回复时显示重试按钮，而不是无限旋转。加载 `AnimatePresence` 切换到 `mode="sync"`，这样恢复期间过时的加载退出不会短暂遮蔽就绪内容。（`d8262fab`）

- **`bunfig.toml` 链接器固定为 `hoisted`** — Bun 1.3 将默认值改为 `isolated`，但该仓库的 Vite + esbuild 打包期望 hoisted 布局（i18next、croner、pdfjs-dist、@tiptap/* 必须解析到顶层 `node_modules`）。Windows 构建脚本已为此使用 `--linker=hoisted`；在 `bunfig.toml` 中固化它消除了平台特定的发散。（`9ae87dc1`）

- **Docker 镜像现复制 `bunfig.toml`** — 没有它，容器使用 Bun 默认的 `isolated` 链接器，导致 Vite 构建失败。（`cbed3061`，`1e85b5a2`）

- **`webui` 运行时 npm 依赖和工作区依赖现明确声明** — `apps/webui` 通过 hoisted `node_modules` 布局隐式继承依赖。将 `@u-agents/{shared,ui}` 声明为工作区依赖，并列出源码实际导入的每个运行时 npm 包，保持包自包含和 Docker 构建可重现。（`7fd8177f`，`9c9eb073`）

## 缺陷修复

- **回环自定义端点 API 密钥现随请求发送** — 配置为回环主机（`localhost`、`127.0.0.1`）的自定义 OpenAI 兼容端点，API 密钥在传出请求中被静默剥离，导致需要认证的本地代理返回 401。密钥现在不变地流动。修复 (#636)。（`62c65169`）

- **自定义端点的视觉覆盖端到端保留** — 自定义端点模型能力现可通过滚动和提示词变更保留明确的每模型 `supportsImages: true` / `supportsImages: false` 覆盖。特别是 `supportsImages: false` 可用于覆盖全局端点图像默认值。（`81259d0b`）

- **Mermaid 验证与渲染器对齐** — `mermaid_validate` 和应用内图表渲染器使用相同的解析器配置，因此通过验证的图表现在实际可以渲染，验证错误反映渲染器的错误报告。（`8b39c84c`）

- **过时重连不再导致会话列表不刷新** — 重连后，会话列表可能保持为重连前状态，直到用户手动刷新。列表现在在重连时权威刷新。（`3a2f7b6b`）

- **飞书交互卡片可靠渲染** — 新飞书适配器的一系列修复：卡片构建器的 schema-2.0 包装器（`body` 下的 `elements` 而非顶层）、按钮 schema（`behaviors[]` 而非遗留的 `action` 包装器）、从 axios `response.data` 提取错误（使飞书的错误码/消息浮现在日志中而非模糊的 axios 字段），以及 WS 生命周期和事件到达诊断日志。SDK 调度器的扁平化事件负载代码路径现得到处理。计划提交、允许/拒绝按钮和接受计划按钮均实现端到端工作。（`d47b6648`，`8cc5fb3f`，`23576f15`，`d7126b80`，`1273a1d0`，`b958ae4f`）

- **飞书连接对话框在绑定后自动关闭** — 配对成功后，对话框现自动关闭并显示确认提示，与 Telegram 流程一致。会话菜单连接子菜单现列出飞书以及 Telegram 和 WhatsApp。（`ef8884f5`，`6e3455f7`）

- **WebUI OAuth 弹出窗口在 iOS Safari 上可用** — iOS Safari 严格的弹出窗口拦截语义要求 OAuth 弹出窗口在用户手势处理程序内同步打开。流程现在复用预打开的窗口，在计算认证 URL 后导航到该窗口，而非在异步回调内打开。（`5e0e7d1d`）

## 破坏性变更

- 对用户无影响。Claude SDK 运行时变更属于内部变更——无需配置更改。自定义端点配置、自动化和消息绑定均保持不变。

## 备注

- 从 0.8.13 升级的工作区在下次安装时每平台应用体积增加约 210 MB——这是新的 Claude Agent SDK 打包模型的内在变化（原生 `claude` 二进制文件现按平台分发，而非 `cli.js` 脚本）。无需操作。
- 完整飞书设置指南位于 [u-agents.u-studio.cn/docs/messaging/lark](https://u-agents.u-studio.cn/docs/messaging/lark)。配置自建应用时，**加密密钥**字段留空——长连接模式不使用 Webhook 负载加密，填写它会静默破坏入站事件。
