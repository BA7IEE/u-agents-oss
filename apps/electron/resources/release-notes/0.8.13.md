# v0.8.13 — 队列消息提示优化、DeepSeek 工具调用恢复、自动化推理覆盖

## 新功能

- **自动化提示动作可设置逐动作思考级别** — `automations.json` 中的提示动作现支持 `thinkingLevel`，与现有的逐动作 `llmConnection` 和 `model` 覆盖选项一致。该值在共享 schema 中验证，通过待处理提示和"运行测试"RPC 路径传播，并以与手动会话相同的工作区默认回退语义传递给生成的自动化会话。已保存的遗留 `"think"` 值在配置解析时迁移而非破坏性中断。（3f8a7d13）

- **自动化动作行现显示模型选择徽章** — 自动化信息页在每个提示动作下以紧凑徽章形式显示配置的连接、模型和思考级别覆盖，使用户无需打开 `automations.json` 即可审查哪个自动化将在哪个模型上运行。（78d08edd）

## 改进

- **队列中的流式消息现明显确认，不使用发光气泡** — 当代理已在响应时用户发送消息，乐观用户气泡保持至少 2.5 秒的脉冲"排队中"内联指示器，包括后端确认几乎立即到达的 Pi/DeepSeek/OpenAI 兼容会话。待发送用户气泡不再使用全局闪烁叠加；排队标记是唯一的瞬态视觉状态。最终实现保持乐观 React 键稳定，因此服务器的规范消息 ID 不会重置计时器。修复 (#616)。（eb81086e, 0d9ca6b5, 083e6f90, 67353f42, fee4c2d1）

- **OpenAI 兼容工具调用失败现产生可操作诊断** — 统一网络拦截器在请求发送到提供商前验证传出的 Chat Completions 和 Responses API 正文，用规范的请求摘要丰富模糊的空正文 `400` 响应，并报告格式错误的历史记录，提供结构化错误详情，而非让会话困在提供商特定消息中。部分解决 (#612)。（ab3c8eac）

- **拦截器开发现使用 monorepo 运行中的实时源码** — 非打包的 Pi 子进程直接预加载 `packages/shared/src/unified-network-interceptor.ts` 而非过时的构建捆绑包，因此拦截器更改在子进程重启后立即生效。新增 `CRAFT_DEBUG_SSE_RAW=1` 开关可将原始 OpenAI 兼容 SSE 行转储到 `interceptor.log`，用于诊断中继行为。（13d13635）

## 缺陷修复

- **DeepSeek 和 OpenAI 兼容工具调用不再因重复或缺失 ID 破坏回放历史** — 流式重组现 deduplicates 重复 `tool_call.id` 的中继，处理提供商在参数增量上省略 `tc.index` 的情况，并将 DeepSeek 的两阶段 `id/name` + 移位参数流合并为每调用的一个逻辑工具调用事件。Responses API 回放现为缺失的 `call_id` 值合成确定性合成，并在孤儿输出时丢弃。Responses API 回放时在回放时清除已损坏的历史（移除空 ID 工具调用和孤立工具结果），因此受影响的会话无需手动编辑 JSONL 即可恢复。修复 (#613)、(#621) 和 (#602)。（ab3c8eac, 13d13635）

- **队列消息在静默重定向期间保留在聊天中** — 渲染器现区分显式用户停止和静默后端重定向：队列气泡仅在有意停止时恢复到输入，而后台重定向将气泡留在聊天中供后端回放。`sendMessage` 现以 `{ accepted, messageId }` 确认持久化，队列回放失败发出类型化可重试错误，队列边界日志使支持分类更容易。修复 (#616)。（eb81086e）

- **Pi/Codex mini 完成避免在 ChatGPT 账户认证下使用不支持的 `codex-mini` 变体** — 标题生成、摘要和 mini 完成现在为 `openai-codex` ChatGPT 账户连接选择时过滤整个 `codex-mini` 系列，防止在查询前出现"使用 Codex 与 ChatGPT 账户时不支持"的失败。（95618531）

- **Pi 内置工具安全接受 Craft UI 元数据** — 严格的 Pi 工具 schema 现允许适配器边界上的根级 `_displayName` 和 `_intent` 字段，然后在调用上游工具实现前剥离它们。这保留了更丰富的工具调用 UI 元数据，而不会在内置工具上触发架构验证。（16d103d2）

- **附件在发送后清除** — 作曲家现消息发送后清除已附加的文件，而非留下已附加文件以备意外重发。（70f9a80a）
