# v0.8.10 — 消息网关、Telegram & WhatsApp 及扩展上下文修复

## 新功能

- **消息网关 — Telegram & WhatsApp** — 新的工作区范围的网关允许你将外部聊天（Telegram 私信、WhatsApp 联系人）绑定到 U Agents 会话。入站消息驱动代理，代理输出渲染回聊天。三种响应模式：`progress`（默认——一个演进气泡）、`streaming`（实时编辑）、`final_only`（静默直到完成）。Telegram 支持照片/文档/语音/视频/音频附件（20 MB 上限）。WhatsApp 在基于 Baileys 构建的子进程工作线程中运行，将其全局状态与主进程隔离。包括新的**设置 → 消息 V2** 页面，每个平台一个磁贴，配对对话框、QR/代码连接 UI 和状态原子。

- **Opus 4.6 恢复为可选择模型** — Claude Opus 4.6 在模型选择器中与 4.7 并列恢复。遇到大型项目"无效请求"的 Tier 1–3 用户可回退到 4.6，无需手动编辑配置。

- **新增 `xhigh` 思考努力级别** — 在 `high` 和 `max` 之间添加中间思考努力级别。

- **Pi-agent stderr 在 LLM 连接测试失败时暴露** — 失败的 LLM 连接测试现暴露底层 pi-agent stderr，使配置错误（缺少二进制文件、认证问题）无需深入日志即可调试。

## 改进

- **思考级别枚举从单一元组派生** — `ThinkingLevel` 及其 Zod schema 现从单一事实来源元组派生，防止类型和运行时验证器之间的漂移。

- **消息 UI 优化** — 淡化对话框提示样式和主连接按钮；将 WhatsApp"忘记设备"菜单项重命名为"断开连接"以提高清晰度。

- **WhatsApp 自聊天优化** — 自聊天回复前缀 🤖，使机器人消息与你自己消息视觉区分；LID（长 ID）联系人现受支持；构建来源已嵌入，因此我们可以在运行时验证捆绑的工作线程。

- **Docker 构建健壮性** — 为 webui Vite 构建将 Node 堆提升至 4 GB，避免精简 CI 镜像上的 OOM。

- **WhatsApp 工作线程 CI 验证** — WhatsApp 工作线程捆绑包现已在 CI 中构建并在发布工件中验证，因此损坏的捆绑包无法发布。

## 缺陷修复

- **扩展上下文（1M）现为选择性加入** — `enable1MContext` 之前默认为 `true`，导致大型项目上直接 API 用户的 Tier 1–3（`context-1m-2025-08-07` beta 需要 Tier 4+）出现 400"无效请求"错误。新安装默认为关闭；用户通过**AI 设置 → 性能 → 扩展上下文（1M）**选择加入。保留现有保存的值。`invalid_request` 错误路径现专门处理 1M 上下文提示，显示"1M 上下文不可用"消息和设置操作，而非误导性的"移除附件"回退。（修复 #567）

- **`spawn_session` 现展开 `workingDirectory` 中的 `~`** — 之前波浪号按字面量传递给子 SDK，产生误导性的"找不到 cli.js"错误。（修复 #575）

- **`set_session_labels` 现接受带值标签（`id::value`）** — 解析器将每个输入作为原子 ID 比较，因此 `"priority::3"` 或 `"parent-task::TASK-123"` 即使基础标签配置了 `valueType` 也始终落入"未知标签"。带值输入现先解析后匹配；值也根据声明的类型（`number`、`date`、`string`）检查，拒绝消息逐条目解释确切原因。（修复 #566）

- **Google 默认模型重新排序** — 连接测试现选择稳定默认模型，而非可能被限流或弃用的模型。

- **Pi-agent codex-mini 拒绝恢复** — `pi-agent-server` 现当 codex-mini 在 ChatGPT 认证 Codex 上拒绝请求时优雅恢复，而非让会话处于损坏状态。

- **注释：后续岛屿关闭推迟到进入动画宽限期之后** — 修复了后续岛屿在其进入动画完成前关闭导致视觉卡顿的竞争条件。

- **Opus 4.6 恢复 wire 格式** — Opus 4.6 现作为 `ModelDefinition` 对象（而非裸字符串）推送，因此连接列表消费者类型检查正确。

## 破坏性变更
