# v0.8.11 — 消息推送、提示词、聊天与 LLM 缺陷修复

## 缺陷修复

- **WhatsApp `selfChatMode` 现对称阻止入站** — `classifyInbound` 之前仅过滤出站（`fromMe=true`）流量，因此在自聊天模式开启时，联系人私信或群消息仍路由到绑定会话——代理可以代表用户在非自聊天中回复。入站非自聊天现已在 `selfChatMode` 开启时被丢弃，并新增 `non_self_chat_inbound` 跳过原因以提高日志清晰度。保持兼容性：`selfChatMode=false` 时，联系人的入站仍如前发出。

- **`call_llm` 在 SDK 最大回合时恢复部分输出而非失败** — `queryLlm` 的 SDK `maxTurns` 为 1，因此自然跨多个 SDK 回合的推理模型输出（即使没有工具）也以"已达到最大回合数 (1)"直接失败。提高到 10，消费者现防御性处理：在 SDK 产出错误结果或流中间抛出时捕获部分助手文本 + 警告，而非返回裸失败。`call_llm` 渲染 `[部分结果 — …]` 使调用方看到信号。添加 `[queryLlm]` 调试日志（子类型、回合数、stop_reason、错误）以缩小可观察性差距。（修复 (#544)）

- **Pi 后端遵从 `includeCoAuthoredBy: false`** — Pi 会话调用 `getSystemPrompt()` 时没有 `includeCoAuthoredBy` 参数，因此静默默认为 `true` 并在用户禁用协作者属性时仍渲染 Git 约定块。镜像了仅在 Claude 路径上修复的早期修复。`getSystemPrompt` 也新增防御性回退：如果调用方省略参数，它解析为保存的 `getCoAuthorPreference()` 值而非硬编码 `true`。（修复 (#576)）

- **后续引用完整发送给代理** — 大型后续注释引用在到达代理前被静默截断至约 280 字符，因为共享的 `normalizeExcerptForMessage` 帮助函数的工具提示调整默认上限适用于代理面向路径。代理路径现使用 `normalizeFollowUpText`（仅空白折叠，无长度上限）；徽章帮助函数重命名为 `truncateForChipTooltip` 并需要明确的 `maxLength`。还删除了死代码 140 字符 `noteLabel` 预截断。（修复 (#580)）

## 改进

- **聊天后续帮助函数提取并单元测试** — `formatFollowUpSection`、`truncateForChipTooltip` 和 `normalizeFollowUpsMarkdown` 从 `ChatDisplay.tsx` 移出到同级 `ChatDisplay.follow-ups.ts` 模块，包含 13 个针对性测试，涵盖 >1000 字符引用回归、规范消息形状、多后续编号、往返解析器和徽章工具提示行为。新增窄幅 `@u-agents/ui/annotations/follow-up-state` 子路径导出，使测试可以导入纯帮助函数，而无需通过 UI 桶拖累 pdfjs + Vite 特定导入。

- **`queryLlm` SDK 流消费者提取以提高可测试性** — 移入 `claude-llm-query.ts`，新增 12 个测试，涵盖抛出/产出错误路径、结构化输出和 `call_llm` 渲染块。

- **预提交类型检查现自动发现 TS 工作区** — `scripts/typecheck-staged.sh` 之前硬编码了 8 个工作区许可名单，因此较新或重命名的工作区（`messaging-*`、`apps/cli`、`apps/webui` 等）中的暂存 TS 更改静默跳过钩子。它现遍历 `apps/<X>/` 和 `packages/<X>/` 并对有 `tsconfig.json` 的任何工作区进行类型检查，优先使用定义时的 `bun run typecheck`。显现并修复了旧许可名单隐藏的四个现有 TS 错误（`apps/cli` Webhook 类型、`apps/marketing` lib 升级到 ES2023 + `card.codeHtml` 重命名 + 索引访问守卫、`apps/webui` 与 Electron 的 tsconfig 对齐）。

- **`electron:dev` 现启动时构建 WhatsApp 工作线程** — `scripts/electron-dev.ts` 构建了 MCP 服务器和 Pi agent 服务器，但未构建 WhatsApp 工作线程，因此新鲜 checkout 在用户首次尝试连接 WhatsApp 时遇到 `MODULE_NOT_FOUND`  `dist/worker.cjs`——令人困惑，因为 Electron 适配器将其报告为工作线程退出，而非缺少构建错误。开发设置现调用规范 `scripts/build-wa-worker.ts`（约 70 ms），使工作线程捆绑包在每次启动时保持同步。

## 破坏性变更
