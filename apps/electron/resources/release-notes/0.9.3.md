# v0.9.3 — 移动/紧凑 UI 重构、Manifest provider 预设、超大工具结果会话毒化修复、Telegram 自动重连

## 新增功能

- **Mobile-first 紧凑模式** — Renderer 整体重构，让同一棵 Electron React 树能优雅地适配窄视口。桌面应用在窗口缩到 768px 以下时自动切到紧凑模式。要点：(a) `isAutoCompact` 由 `@container/shell` 宽度推导 —— 在 navigator（会话列表 / sources 等）与聚焦内容面板之间走 iOS 风格的单栏 drill-in；侧边栏和右侧栏自动收起，布局贴齐视口边缘。(b) 移动优先的 `AppMenu` —— 全屏导航栈 `MobileAppMenu` 从原组件中抽出，桌面分支 `DesktopAppMenu` 完全保留原有行为。(c) 触屏优先的 picker —— workspace switcher、source picker、permission-mode 选择器、会话列表 filter 在紧凑模式下全部从 Radix popover 切到 vaul `Drawer` 底部抽屉（Radix portal 跑到 panel container query 之外，在窄视口下会被裁掉）。(d) Top bar 重排 —— workspace pill 移到左侧，action chip 折叠，`+ 新建会话` FAB 钉在视口底部右侧（通过 portal 跳出 navigator 的 transform 容器，让 `position: fixed` 真正相对视口）。原有 CSS 全程使用 container query，所以桌面布局（≥768px）结构上完全不变。

- **Manifest 加入 API-key provider 预设** — 在 API-key provider 预设里加入 [Manifest](https://manifest.build)（OpenAI 兼容端点 `https://app.manifest.build/v1`），与 HuggingFace、Vercel AI Gateway 等 OpenAI 兼容选项并列。走和 `custom` 预设同一条路径（固定 `customEndpoint.api='openai-completions'`，跳过 Pi model discovery，`piAuthProvider='openai'`）；新增的 `OPENAI_COMPAT_CUSTOM_URL_PRESETS` 集合承载这一类，未来非 Pi SDK 的 OpenAI 兼容 provider 可以一行加入。默认 model 字段以 `auto` 预填，匹配 Manifest 的路由模型 —— `handleBaseUrlChange` 在用户**手动输入** `manifest.build` URL 时也会预填同样默认值（之前只有点击预设的路径会预填）。

## 缺陷修复

- **超大工具结果导致的会话毒化** — Read 一个 base64 比例高的文件可能把会话推过模型上下文窗口，之后**每次重试都返回 `invalid_request`**，唯一的"修复"是放弃该会话。两个叠加的 bug 一起修：(a) 原来的 `chars/4` token 估算对密集 base64 低估约 25%，所以 15K-token 的溢出阈值触发太晚；新的 `estimateTokensDensityAware()` 在 ≥20KB 的工具结果中检测到 ≥70% 的内容是连续 base64 字符段（≥100 字符）时切到 `chars/1.5`，并把 `TOKEN_LIMIT` 降到 12000 留出余量。(b) `invalid_request` 错误的 UX **主动误导**用户 —— hardcoded fallback 建议（"试试移除附件 / 检查图片格式是否支持"）不管发了什么或 API 返回什么都会出现，因为两个真正的错误来源在 Claude SDK 路径上都是死的（`parseApiErrorFromDebugLog` 读的是 SDK 不再写的文件；网络拦截器只在 Pi 上跑）。现在：把过载的 `ONE_M_CONTEXT_HINTS` 拆成 1M tier 专属（`context-1m` / `tier`）和通用 context 溢出（`context window` / `prompt is too long` / …）；通用溢出路由到新的"Context Window Exceeded"错误，建议用 `/compact` 或开新会话；"移除附件"建议只在 API 消息真正提到 image/attachment/media/format **或者**当前用户回合确实包含附件时才出现（`ClaudeSdkErrorContext` 新增 `userTurnHadAttachments` 字段）；两个错误来源都没细节时，追加一个指向 `~/Library/Logs/@u-agents/electron/main.log` 的提示。

- **Telegram 轮询失败后自动重连** — Telegram 轮询停止时（最常见是两个 app 实例共用同一个 bot token 造成的 409 Conflict），`connected` 会永久停在 `false`，之后任何走 `telegramTopic` automation 路由的会话事件都被静默丢弃 —— binding 建立了、会话也跑了、回复也生成了，但什么都没到 Telegram。`TelegramAdapter` 现在对任何轮询失败都调 `scheduleReconnect()`，指数退避：409 用 30s 基数（给竞争进程退出的时间），其它错误 5s 起，封顶 5 分钟。`destroy()` 取消任何待处理定时器，避免有意关闭时再进入循环。`MessagingGateway.onSessionEvent` 现在还会记 `warn` 日志（`adapter_not_connected`）而不是静默继续，未来断线会立刻出现在 `messaging-gateway.log` 里。

- **WhatsApp 语音消息 / 音频附件正常投递** — WhatsApp worker 之前把音频附件静默丢弃，没转发给会话。worker 现在正确发出音频/媒体附件。

- **`source_test` 把 OAuth/bearer token 转给 MCP probe** — 之前对运行时能正常工作的 OAuth MCP source，连接 probe 会报 `invalid_token` —— 原因是 `source_test` 没把 access token 传给 probe。修复：access token 现在会转给 probe，与运行时鉴权对齐。

- **Telegram 权限按钮幂等 + 解决后清掉键盘** — 权限按钮在快速点击时可能重复触发；inline keyboard 在权限解决后也会保留。现在按钮是幂等的，权限被允许 / 拒绝后键盘立刻清掉。

- **空会话上的 model picker 暴露 connection switcher（针对单 model 的 `pi_compat` 默认连接）** — 当一个 workspace 的默认连接是只有一个 model 的 `pi_compat` 连接时，model picker 之前会把整个 connection switcher 隐藏，导致空会话上根本切不到其它 provider。picker 现在即使在这种情况下也会暴露 connection switcher。

## 改进

- **设置图标统一性整理** — `SettingsIcons.tsx` 精简约 180 行，所有设置子页共享同一套图标样式。

- **紧凑模式收尾** — 紧凑模式上线过程中发现的一系列小问题一并修掉：在 resize 时切换 `isCompact` 触发的 React #300（Maximum update depth）；新建会话 FAB 通过 portal 钉到视口底部以让 `position: fixed` 正确解析，并在打开会话时隐藏；PanelHeader 标题在面板宽度上居中；窄视口下的 toggle + topbar 尺寸调优；紧凑模式 mobile header 控件的细节打磨。

- **AppMenu：移除历史桥 + 紧凑模式下去掉键盘快捷键行** — 菜单原来有一个历史桥会在浏览器后退时回滚菜单导航，已移除。键盘快捷键行在 mobile 菜单中也去掉了（触屏场景下不相关）。

## 破坏性变更

- 无。所有变更向后兼容。

## 备注

- **移动/紧凑模式触发条件**：当 shell 宽度降到 768px 以下时自动启用，不区分桌面 app 还是 WebUI。把桌面窗口拖窄就能试。

- **Token 估算变更**：新的密度感知溢出阈值应该能让多数 context 窗口崩溃从源头被挡住。如果你之前对一个 binary 比例高的文件 `Read` 之后看到 `invalid_request: remove attachments` 但其实并没有发附件，那个误导性错误已经消失 —— context 溢出现在会路由到独立的"Context Window Exceeded"错误，指向 `/compact`。
