# v0.9.2 — OAuth 刷新时序、Pi 系统 prompt 持久化、跨机生成保护、source_test/流式/浏览器热修

## 缺陷修复

- **OAuth token 在 agent 构建之前就刷新好** — 冷启动会话发第一条消息时，`SessionManager.sendMessage` 走的顺序是 `getOrCreateAgent` → `buildServersFromSources` → `refreshOAuthTokensIfNeeded`，第一次构建拿到的还是过期 token，触发 `AUTH_REQUIRED`，上层调用 `markSourceNeedsReauth` 把磁盘上的 `isAuthenticated` 翻成 false，用户会先看到一闪即逝的"需要重新授权"提示，然后 refresh 才把状态拉回正常。三处协调修复：(1) refresh 提前到 `getOrCreateAgent` **之前**，让冷启动构建直接拿到最新 token；旧的 `refreshOAuthTokensIfNeeded`（带条件 rebuild）整段删除，每次发送只构建一次。(2) 凭据仅是过期但可刷新时，`buildServersFromSources` 把 `AUTH_REQUIRED` 重分类为 `TOKEN_EXPIRED`，不再调 `markSourceNeedsReauth`，避免冷却期跳过 refresh 时仍闪烁。(3) `TokenRefreshManager.ensureFreshToken` 的失败分支也同步内存中的 `source.config`，让 `isSourceUsable()` 返回 false，确保 refresh 后构建会跳过失败 source。

- **Pi 后端的系统 prompt 不再被悄悄丢掉** — Pi SDK 0.72.1 的 `session.prompt()` 每轮都会把 `agent.state.systemPrompt` 重置回 `_baseSystemPrompt`（`agent-session.js` 大约 L796），所以 `pi-agent-server` 直接赋值的方式被静默吞掉 —— 偏好、笔记、`<session_state>`、`<sources>`、工作目录这些 U Agents 注入的系统 prompt 内容统统失效。Anthropic 后端因为走 SDK 的 `append:` 选项（原样追加）不受影响。新增的辅助函数 `applySystemPromptOverride()` 把同一份 prompt 同时写到 SDK 的**三处**私有字段（`state.systemPrompt`、`_baseSystemPrompt`、`_rebuildSystemPrompt`），保证每轮重置和工具变更触发的重建都不会再丢。这套思路与社区项目 OpenClaw 的同名实现一致 —— 同一个 SDK、同样的限制、已经验证过的兜底方案，等上游放出公开 API 再切。两处旧的 `state.systemPrompt = …` 调用点（每轮的 `prompt` 处理函数、临时的 `queryLlm` 会话）都已切到新辅助函数。回归测试断言三个字段都被写入，防止以后任何一处再被漏掉。

- **跨机器导入会话首次发消息不再撞 spawn 错误** — SDK 的 `Claude Code native binary not found at …` 报错其实是 `spawn ENOENT` 的误导性外壳 —— 子进程的 `cwd` 缺失也会触发，并不只是二进制缺失。跨机器会话导入会保留源机器的 `branchInfo.sdkCwd`，所以**发送到工作区**的接收方在导入会话发第一条消息时，即使应用包完好也会撞这个错。新增的 pre-spawn 保护在 `chatImpl()` 中检测过期的 `branchFromSdkCwd`，走与原有失败后路径相同的 branch fallback 恢复（父级摘要注入照常进行）。新的 `onBranchForkInvalidated` 回调一次性原子写盘四个 fork 字段 —— 顺手修了一个老 bug：原来 `onSdkSessionIdCleared` 只写 `sdkSessionId`，过期的 branch 字段会留在磁盘上等下次启动重新加载。ENOENT 分类从 `if (isProcessError)` 中提出来（SDK 抛的是 `ReferenceError`，根本不会进 `isProcessError` 分支），现在能区分 `binary` / `cwd` / `unknown` 三种成因，重试用尽后给出类型化的 `sdk_binary_missing` / `sdk_cwd_missing` 错误，并保留 2 秒自动重试，覆盖自动更新换包的时间窗。辅助函数抽到 `agent/spawn-helpers.ts` 单独单元测试（新增 34 个测试，原 branching 套件扩展支持 v2 回调）。

- **`source_test` 的 `lastTestedAt` 终于持久化了 —— UI 不再永远显示"从未"** — `source_test` 处理函数原来写的是 ISO 字符串（`new Date().toISOString()`），但 `validators.ts` 里的 Zod 校验器要求 `z.number().int().min(0)`，字符串落盘前被静默丢弃。又叠加一个隐藏不匹配：`session-tools-core/src/types.ts` 把 `lastTestedAt` 声明成 `string`，而权威的共享类型早就改成 `number`。修复就两步：处理函数切到 `Date.now()`，本地类型改回 `number`。存储、校验器、UI（`formatRelativeTime`）本来就按毫秒时间戳处理，其他文件零改动。

- **助手消息完成后不再变空** — `handleTextComplete` 原来无条件用 SDK 完成事件里的 `event.text` 覆盖流式累计的消息内容，一旦 `event.text` 是空（SDK 竞态、或者中间事件没文本），消息气泡就空了。现在两条路径（更新已有消息 / 新建消息）都从 state 里取 `streaming` 做 fallback：`event.text || streaming?.content || existingMsg?.content || ''`。

- **浏览器开关现在能彻底关掉系统 prompt 段落和先决条件规则** — 同一个 `getBrowserToolEnabled()` 开关原来只接到 `session-scoped-tools.ts`，留下三个漏网点：(a) **系统 prompt：**`system.ts` 不管设置如何，都会注入 `## Browser Tools` 段和"调用前必须先 read browser-tools.md"警告 —— 现在受开关控制。(b) **先决条件匹配范围太宽：**`prerequisite-manager.ts` 原本用 `isBrowserToolNameOrAlias()` 匹配，连 `mcp__playwright__browser_tool` 这种外部 MCP 工具也会被误判 —— 收窄为只匹配会话内置规范名（`'browser_tool'` 和 `'mcp__session__browser_tool'`）。(c) **规则总是注册：**功能关闭时这条先决条件规则仍然注册，导致外部 browser 工具被错误拦截 —— 现在 `getBrowserToolEnabled()` 关闭时规则变成空操作。



## 改进


- **Spawn 保护代码经 SOLID/KISS 评审瘦身** — 在保留 spawn-ENOENT 修复中真正承重的部分（pre-spawn 保护、原子的 `onBranchForkInvalidated`、可工作的 ENOENT 分类、识别 `.app` 包的正则）的同时，回滚那次修复里识别出的过度抽象。把 `pickFirstExistingDirectory` 和 `probeEnoentPaths` 内联回原位；删掉 `classifyEnoentCause` —— 4 行的目录循环和 2 行的探测在单一调用点不值得抽象。catch 块里 `binary | cwd | unknown` 的三分支判断合并成顺序三步：cwd 过期且有 branch 信息 → 走恢复；首次失败 → 等 2 秒重试；重试用尽 → 抛出指向最可能成因的类型化错误（去掉 5 个分立的 `enoentCause` 分支）。`recoverFromStaleBranchFork` 上 5 值的 `reason` 联合类型简化成单个 `isPreSpawn` 布尔 —— 状态文案是唯一区别。`lastResolvedCwd` / `lastResolvedBinaryPath` 从实例字段降级为 `chatImpl` 内部局部（通过闭包对内层 catch 可见）—— 避免 `chat()` 多次调用之间状态串扰。`ErrorCode` 集中在 `@u-agents/core/types`，由 `errors.ts` 重新导出。净 −206 行，行为无变化；agent 套件 608 个 + server-core 套件 102 个测试全过。

## 破坏性变更

- 无。所有修复都向后兼容。

## 备注

- OAuth 刷新修复改了每次发消息的执行顺序：现在 refresh 在任何 server 构建之前跑一次，而不是等过期构建之后。如果你用了带自定义 OAuth 流程的 API/MCP source，肉眼可见的变化是每次刷新周期写盘次数变少，冷启动不再有"需要重新授权"的瞬时闪烁。无需改配置，无需迁移。
- 跨机器**发送到工作区**的接收方过去在导入会话首次发消息时会撞 *Claude Code native binary not found at …*，这次起静默成功 —— 保护逻辑会走原有的 branch fallback 恢复，并把干净的 fork 元数据落盘供下次启动用。
