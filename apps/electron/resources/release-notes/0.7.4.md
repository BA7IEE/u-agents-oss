# v0.7.4 — 自定义端点与会话分支重构

---

## 新功能

- **自定义端点支持** — 通过 Pi SDK 的 `registerProvider` 连接任何 OpenAI 兼容提供商，带协议选择器、基础 URL 输入和模型注册。修复 (#329)（479d6d25）

## 改进

- **自定义端点 UX** — 协议选择器现出现在基础 URL 输入之前，编辑状态持久化在设置路由中可靠工作（aac754d7, d94d36bd, 40b53170）

- **CustomEndpointApi 清理** — 去重类型定义，提取 `InitMessage`，并修复模型注册替换 bug（8f770f62）

## 缺陷修复

- **会话分支重构** — 完全重做分支/分叉流程以消除预检失败、工作目录不匹配和卡住的会话。分支现首次用户消息时分支而非预检期间，对话在分支点正确修剪，`spawn_session` 名称在侧边栏正确显示。修复 (#392)（a9358817, 1cb1d11c, d337e288, e54f58f0, 0d40bb7e, 7bd83366, 36f46f88, e8db3e2a 及 10 个额外提交）

- **分支截断可靠性** — Pi 和 Claude 分支截断现使用辅助回合锚和血缘守卫，在 UUID 缺失时有正确回退（ebf0fba7, 20f1dc35, 82b19359, 4bfac3a0）

- **Windows：分支重复消息** — Windows `fs.watch()` 对原子写入积极触发，导致 ConfigWatcher 重新广播会话元数据并重复消息。通过 `appendMessage()` 中基于 ID 的去重、签名比较的自触发事件抑制，以及 Windows 上增加到 300ms 防抖修复（65c959f8）

- **Windows：空分支消息** — 分支消息用硬编码源会话路径而非可移植的 `{{SESSION_PATH}}` 令牌保存，导致 Windows 上路径解析失败。在消息复制期间通过从源 → 分支目录重新令牌化路径修复（1ab2c9b8）

- **会话中模型切换** — `ClaudeAgent.setModel` 现正确调用 `super.setModel` 以更新内部模型引用，修复模型更改未生效的情况。部分解决 (#390)（abd1fa4a）

- **JSON 文件链接崩溃** — 点击不存在文件的 JSON 文件链接不再导致应用崩溃（bfcb875d）

- **空文本块 cache_control** — 从 Anthropic API 请求中的空文本块剥离 `cache_control`，防止验证错误（4ad37ff3）

- **自动化发送超时** — 增加每日讨论要点工作流的发送超时以防止过早超时（669c83cb）
