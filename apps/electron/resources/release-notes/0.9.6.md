# v0.9.6 — 自动更新保留多窗口状态、API source 凭证会话内刷新 + URL 安全加固

## 新增功能

- **多窗口时标题显示工作区名** — 只开一个窗口时标题保持 App 名（"U Agents"）。开第二个窗口后每个窗口的标题变成各自所属工作区的名字，在 Cmd-Tab、Mission Control、Windows 任务栏中一眼可分。Renderer 静态 `<title>` 标签的自动同步被禁用，防止覆盖主进程设置的标题。

- **新增 `markdown-preview` 内联代码块用于渲染 `.md` 文件** — `markdown-preview` 与 `html-preview` / `pdf-preview` / `image-preview` 同模式：用绝对路径引用一个 `.md` 文件，聊天就会通过共享 Markdown 组件渲染它。带 `disablePreviewBlocks` 守卫防止 `markdown-preview` 内嵌 `markdown-preview` 递归（其它嵌套 preview 块不受影响）。在 `minimal`（assistant 聊天）和 `full` 两个模式都已注册，支持 `items` 数组多项展示。

## 改进

- **Messaging gateway 文档反映 0.9.5 fallback 修复** — 澄清 `progress` 和 `final_only` 两种模式在工具调用结尾无干净 `text_complete` 时，现在都会回退到最近的 assistant 文本，而不是 progress 模式卡"思考中..."或 final_only 模式静默。真正空跑的场景仍保持静默。

## 缺陷修复

- **自动更新不再丢多窗口状态** — electron-updater（Squirrel.Mac）在 `quitAndInstall` 和 `before-quit` 之间销毁所有 BrowserWindow，原 before-quit 保存路径会用空 snapshot 覆盖 `~/.u-agents/window-state.json`（变成 `{ windows: [] }`），用户每次接受更新都会丢失多窗口布局。`installUpdate` 现在通过 `setBeforeUpdateQuitHook` 回调在窗口还活着时先保存一次窗口状态；before-quit 路径加了空 snapshot 守卫，防止 pre-update 保存被后续覆盖。

- **API source 凭证支持会话内刷新** — bearer / header / query / basic auth 的 source 在工具创建时把凭证快照成静态字符串，导致用 `source_credential_prompt` 刷新过期 token 后，工具仍在用旧值（一直 401 直到重启 session），即使 `source_test` 验证新 token 是工作的。non-OAuth API source 现在通过 credential getter 路由，每次调用都从 vault 读取最新凭证，与 OAuth / renew-endpoint 路径一致。OAuth 和 renew-endpoint source 不变——它们原本就有 `TokenRefreshManager` 刷新机制。

- **authType 切到 `'none'` 时旧 `source_apikey` 凭证不再泄漏** — `'none'` / `'header'` / `'query'` 三种 authType 都映射到同一个 `source_apikey` 槽位。从带凭证的 authType 切到 `'none'` 时旧凭证仍可在该槽位寻址，未来可能在 rebuild 时覆盖 `defaultHeaders`——例如裸凭证值被当成 Cookie header 发出去，而不是新的 `defaultHeaders.Cookie`。`saveSourceConfig` 现在在 API source + `authType:'none'` 时尽力删除该槽位。删除不抛错，也不阻塞 config 写入。

- **危险 URL scheme 被拦时给出原因 + DOM `href` 净化** — react-markdown 的 `defaultUrlTransform` 把 `file:` / `javascript:` URL 净化成空时，anchor 处理器回退到 anchor text，然后 `new URL(text)` 拒绝它，触发通用的 "Invalid URL" toast 但没原因。`DANGEROUS_SCHEMES` 现在按 `scheme → reason` 映射，原因通过 `OPEN_URL` 处理器流到 server-core 和 Electron GUI 两边。错误信息现在写成 `URL blocked (file:). file: URLs are blocked because shell.openExternal can launch local executables on Windows…`。DOM 的 `href` 属性也通过 `defaultUrlTransform` 净化，dangerous scheme 时设为 `undefined`，关闭通过 Electron `setWindowOpenHandler` 和 `will-navigate` 的 middle-click / cmd-click 逃逸路径。

- **`cache_control` 1h TTL 顺序 bug + 误判 "tool not supported"** — 两个 bug 在 Anthropic 连接启用 `extendedPromptCache` 时一起出现。(1) `upgradePromptCacheTtl` 走 system + messages + 顶层 `cache_control` 但跳过 `body.tools`。Anthropic 按 `tools → system → messages` 顺序处理 block，拒绝 `ttl='1h'` 出现在 `ttl='5m'` 之后的请求——任何 tool 上残留的 5m 都会触发 ordering 报错。tools 现在在 upgrade 和 disable-strip 两个路径都先走。(2) `parseError` 把同一个 400 误判成 "Model Does Not Support Tools"，因为启发式命中了 API hint 里的 `tools` 字。过宽的 pattern 被删除，加 final `invalid_request_error / 400` 分支路由通用 Anthropic 400 到 `invalid_request` 而不是 `unknown_error`。

- **移动 WebUI 长模型名不再挤掉发送按钮** — compact bottom-bar 布局左侧每个 item 都是 `shrink-0` 且外层 row 没 overflow 守卫，375 px 视口下长自定义模型名会溢出 row 把发送按钮挤出可视区。`CompactModelSelector` 的 trigger 现在 shrinkable 并带 `min-w-[64px]` 触控目标下限；compact bottom-bar 子元素包进自己的 `min-w-0 shrink overflow-hidden` 组，让模型 label 先截断，发送按钮保持锚定在右侧。

- **Headless 服务器像 Electron 渲染器一样自动重试 `source_activated`** — `[<slug> activated]` 重发逻辑搬进 `SessionManager.processEvent`，headless 部署（WebUI、docker server）现在和 Electron 渲染器一样能链式 source 激活。一个 2 秒内容匹配的 dedup 窗口防止混版本 rollout（旧渲染器 + 新服务器）双发——第一个匹配的 `sendMessage` 赢并占 slot，后续 2s 内匹配的丢弃。Retry timer + pending slot 在 session 删除两个路径上都会取消。

## 破坏性变更

- 无。所有变更向后兼容。

## 备注

- **本版主题是自动更新、凭证刷新、URL 安全的三类稳定性加固**，不引入新功能（除 `markdown-preview` 块）、不升级底层 SDK（Pi SDK / Claude SDK 都保持原版本），是一次以修 bug 为主的版本。
- 多窗口标题、`markdown-preview` 块与 mid-session 凭证刷新都是用户日常可感的改进；URL 拦截原因 + DOM `href` 净化属安全加固，对正常使用无感。
