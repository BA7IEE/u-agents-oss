# v0.9.1 — Telegram 机器人访问控制 / 流式发送模式 / 模型图像支持开关

## 新功能

- **Telegram 机器人白名单与访问控制** — 解决了"任何找到机器人的人都能跟我的 Agent 对话"的问题。两层访问模型：(1) 工作区层面的拥有者（`open` / `owner-only` 两种模式）；(2) 每个绑定独立的访问模式（`继承工作区` / `白名单` / `开放`）。在配对超群里第一个执行 `/pair` 的用户会自动成为工作区拥有者。在 **设置 → 消息 → Telegram** 中切换到 **owner-only** 会同时把所有遗留的"开放"绑定迁移为"继承"，避免任何公开绑定漏网。新增的"允许用户"面板列出所有拥有者并支持移除；"待处理请求"面板会展示被网关拒绝的发送者，让管理员可以选择"允许"（升级为工作区拥有者）或"仅在此聊天允许"（只对该绑定生效，不会自动提升为全局）。Telegram 内联按钮会走和文本命令同样的访问校验，非拥有者无法通过点按钮绕过；机器人发出的消息在平台层会被静默丢弃。机器人解锁入口在平台上下文菜单的"重新配置"旁边，仅在已锁定时显示。

- **每连接的流式发送行为（继续/排队）** — **设置 → AI** 连接的上下文菜单新增子菜单，让你选择 Agent 正在流式响应时你发新消息的行为：
  - **继续**（Steer）：保留原有行为，尝试把新消息注入到当前响应中。
  - **排队**（Queue）：等当前轮次干净结束，再回放排队的消息。
  
  两种模式失败方式不同：Anthropic 后端的"继续"模式可能会因为本轮没有工具调用就提前结束，导致消息白白消耗 token；Pi 后端的"继续"是原生支持，没有这个问题。系统会按 provider 类型自动选默认值（Anthropic → 排队，Pi 系列 → 继续）。

- **聊天输入框中的模型图像支持开关** — U-API（自定义端点）连接现在可以在聊天输入框的模型选择器里，对每个模型一键切换图像支持。如果你贴了图但当前模型不支持图像，输入框上方会出现"启用图像支持"的预检提示。这个开关也支持单模型场景（用了 `defaultModel` 但模型列表只有 0 或 1 项时）。配置变化只是给该连接对应的模型加一个图像支持标志，不影响内置模型目录。

- **工具结果阈值随模型上下文窗口动态调整** — 之前固定 15k token 的阈值在小窗口模型（比如 64k）上一次工具调用就消耗 25% 上下文，三四次中等量的搜索/读取就可能溢出。现在改为动态计算：下限 2k，上限 15k，中间按上下文窗口的 10% 线性缩放（64k → 6.4k，128k → 12.8k）。会话中切换模型时阈值也会跟着变。

## 改进

- **设置 → 消息：多语言文案整理** — 之前"重新配置"/"断开"/"连接"等动词在多个平台命名空间里重复定义，导致中文等非英语界面里偶尔混进英文残留（比如匈牙利语界面会同时出现"Reconfigure"和翻译过的文案）。本次抽出 7 个通用动词翻译到所有非英文语言，统一了 8 处调用点。结果是每种语言的未翻译值从 14-17 个降到 2-5 个（剩下的只是地区名等本来就不译的术语）。今后新增消息平台不再需要重复翻译这些通用动词。

- **多语言文件字典序保护** — 之前各语言文件里 1393 个 key 中有 96 个不是字典序排列。新增 `bun run sort-locales` 命令一键修复，提交前钩子会自动拦截没排好序的语言文件，并提示运行修复命令。这避免了未来翻译合并时无法察觉的对称丢失（多个语言同时少几十个 key 但仍能"配对通过"）。

- **Pi SDK 升级到 0.72.1** — 底层 Pi 模型 SDK 从 0.70.2 升级到 0.72.1，顺带带来：长时间流式响应时网络层不再因空闲超时断开、Anthropic 流结束错误处理更稳定、DeepSeek V4 推理兼容、GPT-5.5 Codex 支持、OpenAI Codex 的 WebSocket 缓存传输优化。无需任何配置改动；之前如果配置了 `google-gemini-cli` 或 `google-antigravity`（上游已移除），这两项不再被识别。

- **HTTP MCP 校验不再启动子进程** — 之前测试 HTTP MCP 服务器是否健康时会启动一个完整的 Agent 子进程，仅仅为了调用一次健康检查。在 macOS 上 Electron 沙箱会在校验完成前用 SIGKILL 杀掉这个子进程，导致每次 HTTP MCP 测试都失败（即使服务器健康）。改为直接用 MCP 客户端调用，去掉了子进程、Anthropic 环境变量切换、Claude 凭证预检等，校验逻辑减少 ~110 行。

- **API 数据源探针支持 POST 端点** — 仅支持 POST 的 API 端点之前会因为探针使用空请求体而稳定 500。现在探针会使用配置中的 `testEndpoint.body`、`testEndpoint.headers`、`testEndpoint.method`，不再做 HEAD→GET 重试的伪装。同时不再每次 LLM 请求都把 `guide.md` 内联进 API 工具描述（Agent 的前置管理器已经会在调用前自动读取 guide）。OpenAPI 导入的数据源每次请求节省数十 KB。

- **IPC 清单脚本自动更新测试快照** — `scripts/ipc-inventory.ts` 现在会就地重写测试文件中的 `EXPECTED_CHANNELS` 块，不再只打印迁移报告。增删改 RPC 通道后跑这个脚本就能同步测试。

## Bug 修复

- **U-API 模型图像支持开关现在能实时同步到运行中的 Pi 子进程** — 之前切换图像支持只写了磁盘但没通知到运行中的子进程，模型仍然看到附件被替换为"(图像已忽略：模型不支持)"占位符。本次修复了三处问题：(1) 配置保存触发的运行时刷新原本被错误地"是否正在处理"标志拦掉，现在改为不阻塞分发；(2) 给每个会话加了刷新互斥锁，避免并发刷新冲突；(3) 需要重启子进程的字段变化（如 Auth Provider、连接 slug、认证路由）现在直接走重建流程，不再尝试热更新。

- **图像支持开关不再让模型选择器按钮变空白** — 之前如果模型配置是字符串数组形式（如 `['gpt-4o']`），切换图像支持时会把字符串"升级"为对象但漏了 `name` 字段，导致选择器按钮显示空白。修复后升级时会自动填充 `name`，并在三处显示点都加了兜底回退。

- **冷会话的元数据修改在重启后保留** — 之前会话刚启动时（侧边栏里所有未打开的会话都处于这个状态），如果你修改了状态/标签/重命名，结果不会写入磁盘——重启后丢失。修复后冷会话的元数据修改会先同步加载消息和 token 使用量，再排队写入。

- **Pi+GPT 上下文溢出不再级联三个错误** — 之前 Pi+GPT 上下文溢出会一次性抛出三条错误：上下文超长 → 自动压缩失败 → "Agent 已在处理"。三个独立根因：Pi SDK 自动压缩存在竞态、`pi-agent-server` 包装层重复触发压缩、事件适配器迭代器过早关闭。引入了 5 状态的溢出恢复状态机来串行处理压缩→恢复流程，移除了重复压缩路径，把超时从 60 秒提到 300 秒匹配 RPC 超时，并在等待修复期间用友好提示替换原始错误堆栈。

- **浏览器面板隐藏窗口不再崩溃** — Agent 工具执行期间隐藏窗口可能导致黑屏崩溃——`close` 监听器可能重入隐藏函数，且状态变更回调在 Chromium 还在拆除时同步运行。修复后加了重入守卫、把状态回调推迟到微任务、加载未完成时先停止 webContents。

- **快速切换工作区不再因初始化竞态崩溃** — 在跨工作区切换并且新工作区已经处于"已连接"状态时，连接状态变化回调会同步触发，导致一个变量在初始化前被引用而抛 `ReferenceError`。修复了取消订阅函数的初始化时机。

## 文档

- **Google OAuth 配置改用 Web 应用类型，不再用 Desktop app** — 较新的 Google Cloud 项目 / Workspace 账号会拒绝 Desktop app 客户端的环回回调地址，导致用户照旧文档配置后会撞 `redirect_uri_mismatch`。"Web 应用"客户端类型在桌面和 WebUI 两种场景下都能用。OAuth 配置文档已统一改为 Web 应用配置示例。

- **流式发送和图像支持开关文档** — 核心概念文档新增"Agent 响应中发送消息"小节解释继续/排队两种模式；连接配置参考新增 `midStreamBehavior` 字段说明；自定义端点配置文档说明聊天输入框图像支持开关的用法。

## 破坏性变更

无。Telegram 访问控制升级到 owner-only 时会自动把遗留的"开放"绑定迁移为"继承"，无需手动改配置。流式发送行为字段对升级前的连接会按 provider 自动取默认值。

## 注意事项

- 升级前已绑定到工作区的机器人在下一次 `/pair` 命令前没有任何拥有者；第一个执行 `/pair` 的用户会被自动设为拥有者。可以在 **设置 → 消息 → Telegram** 的"允许用户"面板查看当前状态。
- 多语言文件字典序检查会拦截未排序的提交。如果你贡献翻译，新增 key 后请运行 `bun run sort-locales`。
- Pi SDK 升级是内部改动，无需配置改动。如果你之前配过 `google-gemini-cli` 或 `google-antigravity`（上游已移除），这两项不再生效。
