# v0.8.12 — GPT-5.5 + DeepSeek 提供商、Pi 工具注册恢复、编辑器与差异优化

## 新功能

- **GPT-5.5 现为 `openai` 和 `openai-codex` 默认模型** — Pi SDK 0.70.0 在 OpenAI 目录中添加了 `gpt-5.5`，因此 `PI_PREFERRED_DEFAULTS` 现将其选为 `openai` 和 `openai-codex` 认证提供商的默认模型，而非 SDK 返回的第一个模型。新 API 密钥连接和 U-API（OpenAI）连接开箱即用 `gpt-5.5`；现有连接保持其明确的模型选择。修复 (#597)。

- **DeepSeek 现为支持的 Pi 后端提供商** — 在 `PROVIDER_METADATA`（仪表板 URL）、`PI_PROVIDER_DISPLAY`（标签 + 占位符）和 `PI_PREFERRED_DEFAULTS`（`deepseek-v4-pro` / `deepseek-v4-flash`）中添加 DeepSeek，使连接默认使用现代模型而非 SDK 返回的第一个模型。渲染器通过 `PI_AUTH_PROVIDER_DOMAINS`（`deepseek.com`）自动获取新提供商用于图标解析、API 设置预设和设置页标签。CLI 新增 `DEEPSEEK_API_KEY` 环境密钥，并将 `resolveApiKey`、`shouldSetupLlmConnection` 和 `getProviderDisplayName` 提取为可测试的导出；`--base-url` 自动设置现适用于非 Anthropic 提供商，验证步骤共享相同的解析器路径。修复 (#600)。

## 改进

- **`source_test` 现自动启用并自动重置回合以便工具立即可调用** — 之前 `source_test` 仅验证源；配置有效但 `enabled: false` 的用户必须手动翻转标志并重启会话，即使每项检查都通过了。该工具现了在需要时翻转 `enabled: true`，并触发会话现有的 `onSourceActivationRequest` 回调，以便 MCP/API 服务器被构建并应用到运行中的代理。（本版本的）后续修复通过相同的 `source_activated` + `auto_retry` 机制路由成功激活，该机制已处理"工具在源未激活时未找到"错误：激活后，当前回合干净中止，渲染器以 `[{slug} 已激活]` 后缀重新发送用户的原始消息——为下一个 `query()`/`handlePrompt` 提供新的实时工具列表。这修复了一个 Claude 特定 bug：`source_test` 报告"工具现在可用"，但 SDK 在查询开始时已冻结了 `mcpServers`，因此 `mcp__{slug}__*` 工具对模型不可见，直到用户输入另一条消息。Pi 为保持一致也这样做（也需要回合边界——其子进程仅在下一个 `handlePrompt` 时获取新的代理工具定义）。使用 `autoEnable: false` 选择退出以保持纯验证行为。 Codex 或其他无激活回调的后端无变化——它们仍获得 `enabled` 翻转和清晰的"重启会话以加载工具"提示。

- **`spawn_session` 接受 `thinkingLevel`** — 代理在委托给生成会话时可设置推理级别（`off` | `low` | `medium` | `high` | `xhigh` | `max`），而非始终继承父会话级别或工作区默认值。在非推理模型上静默忽略（如 gpt-4o、gemini-2.5-flash）：Pi 提供商驱动和 Claude SDK 都将推理参数限制在模型能力上，因此将 `thinkingLevel` 传递给非推理模型是安全无操作而非错误。同时修复了一个潜在 bug：会话管理器 API 中 `createSession({ thinkingLevel })` 被静默忽略——该选项现按调用方 → 工作区 → 全局优先级得到尊重，与 `permissionMode` 的现有工作方式一致。修复 (#462)。

- **Pi-agent-server 的真实类型检查门控** — 包的 `typecheck` 脚本别名到 `bun run build`（打包器，而非 `tsc`），因此 Pi 子进程工具注册的 API 形状漂移未通过 CI（见下文 Pi 子进程工具注册修复的具体回归）。新增专用 `tsc --noEmit -p tsconfig.typecheck.json` 步骤，接入 `typecheck:all`，加上 turndown/pdfjs-dist/bash-parser 的环境填充，使新类型检查无需 @types 包。它表面上的一连串现有类型漂移（`PiCredential` vs `AuthCredential`、`agent_end` 事件形状、`sdkTurnAnchor` 丰富、`CustomModelEntry` 在动态注册调用点、`initConfig` 在 queryLlm 闭包中的可空性，以及 web-fetch `result` 帮助函数中不正确的泛型）。

## 缺陷修复

- **WebUI"添加新标签"不再启动桌面应用** — 在 WebUI 聊天输入中输入 `#<新标签>` 并点击"添加新标签>` 之前会打开一个弹出窗口，提交时触发 `uagents://action/new-session` 深度链接。浏览器通过启动 Electron 桌面应用解析该协议，而非在浏览器中创建标签。根本原因：聊天输入调用点从 EditPopover 配置中挑选字段，丢弃了 `inlineExecution: true`，回退到遗留的同窗口深度链接路径（在 Electron 内部碰巧工作，但在 WebUI ↔ OS 边界上中断）。切换到完整配置展开，与 `AppShell` 已调用相同弹出窗口的方式一致。

- **附件不再在会话间泄露（这次是真的）** — 附加文件、切换会话而不发送、然后切换回来，现跨所有四个附加路径恢复原始会话中的附件（文件选择器、OS 拖放、剪贴板粘贴、Web 拖放）。首次修复假设每个附件都有真实的 OS 路径——文件选择器/OS 拖放为真，粘贴/Web 拖放为假（Chromium 从 Blob 合成 `File` 而无磁盘来源），因此草稿引用回退到仅文件名值并在补水时重新读取失败。新的持久化层是混合的：文件选择器和 OS 拖放通过 `webUtils.getPathForFile`（Electron 32+）捕获绝对路径，并通过专用 `file:readUserAttachment` RPC 在补水时重新读取；粘贴和 Web 拖放将字节内联保存在草稿中（每个附件 20 MB 上限——过大的粘贴记录警告并从草稿中删除）。旧 0.8.11 格式草稿在加载时被拒绝，因此被之前损坏版本保存的附件在升级后消失一次，而非静默困扰作曲家。修复 (#572)。

- **自定义 URL 方案链接现在打开正确的应用** — 点击聊天消息中的 `obsidian://`、`vscode://`、`zed://`、`notion://`、`slack://` 等链接，现分派到 OS 协议处理器，而非被阻止（桌面）或重写为 `https://<host>/obsidian://...`（WebUI）。URL 处理从严格许可名单（`http/https/mailto/craftdocs`）切换到已知危险方案的黑名单（`javascript:`、`data:`、`vbscript:`、`blob:`、`file:`）。WebUI 和查看器现对非 http 方案使用锚点点击回退，使 Chrome 可靠地通过外部协议调度器路由。修复 (#590)。

- **在 GPT 会话上 `/compact` 不再过早超时** — 对 Pi 支持的 OpenAI 模型进行手动压缩（包括在提交的计划上"接受并压缩"）在 60 秒后失败，因为子进程 RPC 没有为 GPT-5.4 在大型会话上的长摘要回复留出空间。将超时提高到 5 分钟——真正挂起的子进程仍被 stdio 死亡看门狗捕获。Claude 会话不受影响（它们使用 SDK 的本机压缩通道）。

- **Pi 子进程工具注册恢复** — Pi SDK 0.70.0 将 `CreateAgentSessionOptions.tools` 从工具对象数组静默重塑为 `string[]` 名称许可名单。子进程继续传递 `AgentTool[]`，因此运行时 `allowedToolNames = new Set(objects)` 和 `.has(name)` 对每次查找返回 `false`——每个自定义工具都被 `_refreshToolRegistry` 的许可名单守卫过滤掉，使 LLM 仅拥有内置的 `[read, bash, edit, write]`。修复现通过 `customTools: ToolDefinition[]` 加匹配的 `tools: string[]` 许可名单路由工具对象，包含每个注册名称，删除私有的 `_baseToolsOverride + _buildRuntime` 纵深防御黑客，恢复上次 0.68 之前捆绑在 monolithic `codingTools` 数组中的 `grep`/`find`/`ls`。回归测试现锁定形状契约（每个 `customTools[].name` ∈ `tools` 许可名单），使下一次 SDK 升级无法再静默删除工具。

- **Pi `call_llm` 遵从请求的模型** — `queryLlm` 通过仅携带 `prompt` 的 `mini_completion` RPC 路由 `call_llm`。因此每个 `call_llm` 静默地在连接的 mini 模型上运行（通常过时的 `pi/gpt-5.1-codex-mini`），忽略 `request.model` 和 `request.systemPrompt`。引入携带完整 `LLMQueryRequest` 的新 `llm_query` RPC；子进程委托给模型感知的 `queryLlm`。`PiAgent.queryLlm` 在结果/通用错误/子进程退出的清理映射中跟踪待处理查询，事件适配器的 `call_llm` 覆盖现仅在缺失时填充 `args.model`（从不覆盖显式值）。往返不变性测试逐字节守卫完整请求信封。修复 (#596)。

- **Pi mini 完成选择提供商合适的模型** — `handleMiniCompletion` 在 ChatGPT Plus / openai-codex / google / github-copilot 上只要连接没有明确的 `miniModel` 就失败，并显示"未找到 openai 的 API 密钥"。`queryLlm` 中的提供商检查回退始终分配 `getDefaultSummarizationModel()`（Haiku），它仅在 anthropic 认证下解析——Pi SDK 0.70.0 默认值然后静默地表观为 OpenAI 模型，误导性认证错误冒泡。新 `pickProviderAppropriateMiniModel` 帮助函数遍历 `PI_PREFERRED_DEFAULTS[authProvider]` 寻找可解析的、非拒绝的候选（明确保留 anthropic 以保持 Haiku 为其 mini 默认），`runQueryWithModel` 现如果无模型解析则以可操作消息快速失败。

- **编辑器不再因格式错误的草稿崩溃** — 加强聊天输入抵御不可信草稿内容：渲染器现边界处强制转换草稿文本，`RichTextInput` 对非字符串值防御，编辑区包装在本地错误边界中，带有恢复操作，因此损坏的草稿不会导致整个窗口崩溃。回退 UI 已本地化并通过暂存 i18n 检查。

- **裸 `@@` 差异块现渲染为丰富的 PatchDiff** — 差异规范化移入纯帮助函数，并为之前回退到语法高亮 `CodeBlock` 而非 pierre 差异查看器的三种形式变得健壮：裸 `@@` 标记行、无文件头的有效编号块，以及已是统一/git 补丁的形式（现逐字节保留）。合成路径在存在时保留用户文件头，干净地剥离块标记，不留空白上下文行，计算正文行而非错误地将合法的 `---` / `+++` 删除/添加内容识别为文件头。

## 依赖变更

- **Pi SDK 升级至 0.70.2** — 根目录、`pi-agent-server`、`server-core` 和 `shared` 中的 `@mariozechner/pi-{coding-agent,agent-core,ai}` 均升级。0.66.1 → 0.70.0 步骤用 `createCodingTools(cwd)` 工厂替换了已删除的 `codingTools` 导出，并重塑了 `CreateAgentSessionOptions.tools`（见上文工具注册修复）。0.70.0 → 0.70.2 步骤是补丁级升级，我们的代码未使用新的 API 面。（见上文 GPT-5.5 新功能条目中 0.70.0 目录启用默认模型变更。）

- **Claude Agent SDK 固定为精确 0.2.111** — 之前的 0.2.111 → 0.2.119 升级导致 Claude 支持的会话出现"找不到 Claude Code SDK"。从 0.2.113 开始，SDK 用平台范围的原生二进制文件（`@anthropic-ai/claude-agent-sdk-{platform}-{arch}`）替换了其 JS `cli.js` 入口点，我们的运行时解析器、构建脚本、CI 验证捆绑步骤和基于 `--preload` 的统一网络拦截器都假设不存在这种东西。固定回退到最后一个基于 JS 的版本，并将 peer-dep 范围从 `^0.2.19` / `>=0.2.19`收紧为精确的 `0.2.111`，使下一次重塑无法作为静默补丁版本。完整原生二进制迁移（拦截器重新归属）单独跟踪。

## 破坏性变更

- 无。`source_test` 向后兼容；`autoEnable` 默认为 `true`，但之前的验证输出是新输出的严格子集。传递 `autoEnable: false` 可精确重现旧行为。`spawn_session` 新增可选字段——现有调用方不受影响。
