## 2. B 路：隐性事故扫描 + R2 闭环路径（B+）

### 2.1 重大新发现：scripts/build/common.ts 8 个 helper **全部死代码**

不只是 v15 C 路说的"dead helper"——是 **parallel/abandoned implementation**。
- 平台 TS 文件（darwin.ts/linux.ts/win32.ts）只 import `BuildConfig` 类型，从不调 helper
- 生产路径走 `build-dmg.sh` / `build-linux.sh` / `build-win.ps1`，把 SDK/ripgrep/interceptor 复制逻辑 **inline 写在 shell/PowerShell 里**

| Helper | 功能 | mac inline | linux inline | win inline | 风险 |
|---|---|---|---|---|---|
| copySDK / verifySDKCopy | 复制 SDK + binary 大小验证 | ✓ | ✓ | ✓ | 零 |
| copyRipgrep | @vscode/ripgrep | ✓ | ✓ | ✓ | 零 |
| copyInterceptor | **复制 .ts 源（dev mode 用）** | ✓ | ✓ | ✓ | 零 |
| copyInterceptorBundle | 验证 dist/interceptor.cjs 已存在 | 未调 | 未调 | 未调 | 轻 |
| copySessionServer | session-mcp-server/dist/index.js | 未调 | 未调 | 未调 | 零（已被 copy-subprocess-servers.ts 替代）|
| **verifyMcpServersExist** | **packaged resources 校验** | **未调** | **未调** | **未调** | **隐性事故 #6 候选** |

**关键澄清**：`copyInterceptor`（复制 .ts 源给 Pi subprocess `--preload` 用）**≠** `buildInterceptor`（产 `dist/interceptor.cjs` 给 Node `--require` 用）。前者三平台 inline 都有；后者就是事故 #5 修的那个。**名字相近功能不同**——文档应明确区分。

### 2.2 隐性事故 #6 候选：verifyMcpServersExist 未接通

[`scripts/build/common.ts:622+`](scripts/build/common.ts) 含 verifyMcpServersExist —— 三平台 build chain 都没调。事故 #4/#5 之所以拖到 Windows 实测才暴露，就是缺这一道闸：**build-time 没有 packaged-resources 校验**，下次同步上游若再加 server，build 阶段就 fail 而不是用户首次启动 fail。

**v15 C 路 agent 的预言"事故第 4 个就在这里等"是对的方向但错的目标**——事故 #4/#5 不是从 dead helper 来的，是 main bundle 5 步流水线 Windows 漏调。但 verifyMcpServersExist 仍是真实的"防御层缺失"。

**P1 长期防护建议**：在 build-dmg.sh / build-linux.sh / build-win.ps1 packaging 完成后跑 packaged-resources 校验。

### 2.3 隐藏炸弹 1：`scripts/upload.ts` **不存在**

[`build-dmg.sh:294`](apps/electron/scripts/build-dmg.sh) 调 `scripts/upload.ts`——但 `scripts/` 目录里**没有这个文件**！

也就是说 `bash build-dmg.sh arm64 --upload --latest` **会 ENOENT 失败**。

之前我推荐 user 跑这个命令是错的——必须用 rclone 手工流程（详 §2.5）。

### 2.4 隐藏炸弹 2：`build:validate` 死代码

[`apps/electron/package.json:25`](apps/electron/package.json) 声明 `"build:validate": "bun scripts/validate-assets.ts"`，但 `apps/electron/scripts/validate-assets.ts` **根本不存在**。

`build` 和 `build:win` script 都引用它，但生产链路都不走这两个 script——所以是 **documentation lie**，不会炸但误导 reviewer。**P2**。

### 2.5 R2 上传 step-by-step（替代 build-dmg.sh --upload）

**前置一次性配置**（你之前可能配过）：
```bash
brew install rclone
rclone config
# remote 名 = r2，type = s3，provider = Cloudflare
# endpoint = R2 S3 API URL（Cloudflare dashboard 拿）
# AK/SK 从 Cloudflare R2 token 拿
```

**每次发版（v0.9.1 三平台 + 4 项 M2 fix + 事故 #4 fix；事故 #5 待 Windows 重打）**：

```bash
cd /Users/dengwang/Documents/u-agents-oss/u-agents
VERSION=v0.9.1

# 1. 准备 manifest.json + latest.json（按 06-update-server.md §4.0 模板）
#    含 sha256 / size / version / arch
#    sha256: shasum -a 256 apps/electron/release/U-Agents-arm64.dmg
#    size:   stat -f%z apps/electron/release/U-Agents-arm64.dmg
# 写到 /tmp/u-agents-manifest.json + /tmp/u-agents-latest.json

# 2. 上传到版本归档 /v0.9.1/
rclone copy apps/electron/release/U-Agents-arm64.dmg r2:u-agents-update/$VERSION/
rclone copy apps/electron/release/U-Agents-x64.dmg r2:u-agents-update/$VERSION/
rclone copy apps/electron/release/U-Agents-arm64.zip r2:u-agents-update/$VERSION/
rclone copy apps/electron/release/U-Agents-x64.zip r2:u-agents-update/$VERSION/
rclone copy apps/electron/release/U-Agents-arm64.zip.blockmap r2:u-agents-update/$VERSION/
rclone copy apps/electron/release/U-Agents-x64.zip.blockmap r2:u-agents-update/$VERSION/
rclone copy apps/electron/release/latest-mac.yml r2:u-agents-update/$VERSION/
rclone copyto /tmp/u-agents-manifest.json r2:u-agents-update/$VERSION/manifest.json

# 3. 切 latest 指针
rclone copy apps/electron/release/U-Agents-arm64.zip r2:u-agents-update/latest/
rclone copy apps/electron/release/U-Agents-x64.zip r2:u-agents-update/latest/
rclone copy apps/electron/release/U-Agents-arm64.zip.blockmap r2:u-agents-update/latest/
rclone copy apps/electron/release/U-Agents-x64.zip.blockmap r2:u-agents-update/latest/
rclone copy apps/electron/release/latest-mac.yml r2:u-agents-update/latest/
rclone copyto /tmp/u-agents-latest.json r2:u-agents-update/latest
# ⚠️ copyto 不是 copy，否则会建 latest/latest 子路径

# 4. Windows 同上加：
rclone copy apps/electron/release/U-Agents-x64.exe r2:u-agents-update/$VERSION/
rclone copy apps/electron/release/latest.yml r2:u-agents-update/$VERSION/
rclone copy apps/electron/release/U-Agents-x64.exe r2:u-agents-update/latest/
rclone copy apps/electron/release/latest.yml r2:u-agents-update/latest/

# 5. 验证（curl HTTPS 应 200 + JSON 含 v0.9.1）
curl -I https://update.u-agents.u-studio.cn/$VERSION/latest-mac.yml
curl https://update.u-agents.u-studio.cn/latest/latest-mac.yml
curl https://update.u-agents.u-studio.cn/latest
```

⚠️ **注意**：Windows EXE 现在是事故 #4 fix 后的版本（commit `8fea0c00` 时打的），**不含事故 #5 fix**。如果上传现在的 Windows EXE，分发到用户机器后 Pi subprocess interceptor 仍不工作（多 MCP 场景受损）。**强烈建议先用 commit `c0fe89cc` 重打 Windows EXE 再上传**。
