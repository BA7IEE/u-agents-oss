### 2.3 **🔴 P0：事故 #5 候选（buildInterceptor 在 Windows 路径漏调，高置信度）**

**精确定位**：

- [`scripts/electron-build-main.ts:332`](scripts/electron-build-main.ts) `buildInterceptor()` 产 `apps/electron/dist/interceptor.cjs`
- macOS/Linux 通过 `bun run electron:build` → `electron-build-main.ts` → 触发 ✓
- **[Windows `build-win.ps1:227-242`](apps/electron/scripts/build-win.ps1) 只 `Copy-Item` `unified-network-interceptor.ts`（**`.ts` 源**）到 `packages/shared/src/`** —— **没有产出 `dist/interceptor.cjs`**
- [`runtime-resolver.ts:168-169`](packages/shared/src/agent/backend/internal/runtime-resolver.ts) 运行时找 `dist/interceptor.cjs`：
  ```typescript
  return resolveUpwards(hostRuntime.appRootPath, join('dist', 'interceptor.cjs'))
    ?? resolveUpwards(hostRuntime.appRootPath, join('apps', 'electron', 'dist', 'interceptor.cjs'));
  ```
- **Windows EXE 包内必然找不到 `dist/interceptor.cjs`** → Pi subprocess interceptor 不工作

**为什么用户实测 Windows EXE 消息回复正常**：interceptor 不影响"首条 LLM 消息"主路径——它的功能是流量监控 + MCP schema 注入 + tool intent capture，缺失不阻塞 LLM 请求-响应。但**多 MCP 场景下功能受损**。

**与事故 #3/#4 的关系**：事故 #3 fix 加了 `electron:build:subprocess`（covers session-mcp-server + pi-agent-server），事故 #4 fix 加了 `build:wa-worker`（covers WhatsApp worker），**但 buildInterceptor 仍漏调**——这是 [`electron-build-main.ts:main()`](scripts/electron-build-main.ts) 5 步流水线的第 3 步，事故 #3/#4 修了 1+2+4，**事故 #5 = 第 3 步**。

**修法**：build-win.ps1 §6 （interceptor 复制段）末尾加 `bun run build:interceptor`（root package.json 已有此 script），加 `# U-API:` marker（B4）+ 进 §3.7 Build 脚本子表。

**严重度**：**P0**（隐性事故；Windows 包内 interceptor 永远不工作；用户感知低但功能受损）。
