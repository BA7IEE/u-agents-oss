## 5. R2 上的 DMG/EXE 与 git 主干的关系

⚠️ **重要协调点**：

| 资产 | git 当前 HEAD（d7ed1719）| R2 上的版本 |
|---|---|---|
| 代码 | 含 hotfix v0.9.0+u-agents.1（5 个 commit）| - |
| `U-Agents-arm64.dmg` 等产物 | 未重打 | **仍是 v0.9.0 首发版**（commit `323293b` 当时打的）|

**含义**：
- 当前 R2 上 DMG = 首发版（**不含 hotfix**）
- 用户自测过的也是首发版
- hotfix 内容仅在 git 仓库，**没在用户能下载的产物里**

**两种处理路径**：

### 路径 A — 重打 hotfix 版（推荐用于种子分发）

1. 跑 `bun run build -- --arch arm64` + `--arch x64` 重打 macOS DMG
2. Windows 端重打 EXE
3. 上传 R2 替换（`latest-mac.yml` + `latest.yml` 自动重新生成）
4. 更新 [M1-SEED-DISTRIBUTION.md](../M1-SEED-DISTRIBUTION.md) §1.1 加注 hotfix 标识

### 路径 B — 保持首发版分发（hotfix 留作下下版）

1. 不重打
2. 当前 R2 首发版直接分发
3. hotfix 内容并入下次自然迭代（M3 / 上游同步后一起发）

**判断依据**：
- 路径 A：种子用户拿到的是最新代码，bug fix 立即生效，但要重打 + 重测
- 路径 B：hotfix 影响面（system prompt + 测试）实际**对单连接首发用户感知极小**——AI 偶尔在长篇介绍里说 "Craft" 这种已经很罕见

**REVIEW-6 建议**：**路径 A**——既然 hotfix 已经做完，重打成本只是 10 分钟构建，但分发出去的 DMG 是"最干净的"，避免后续解释。
