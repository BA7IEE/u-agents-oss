## 1. A 路：代码安全（B）

### 🔴 A-P1：Sentry DSN build-time 注入风险（双视角）

[`scripts/electron-build-main.ts:58`](scripts/electron-build-main.ts) 把 `SENTRY_ELECTRON_INGEST_URL` 列在 esbuild `--define` 白名单——若 `.env` / CI secret 一旦泄入这个变量，DSN 直接 hardcode 进二进制 → 公网 telemetry 静默上线 + 无法回滚。

**A 路视角**：build-time 风险
**C 路视角**：当前实际 build 没注入 DSN → 生产 crash 报告全丢失（observability 失效）

**修法**：build-time 加 assertion——`if (process.env.SENTRY_ELECTRON_INGEST_URL && app.isPackaged) throw` 阻止打包；M3 自建 Sentry 后再放开。

### 🔴 A-P1：refreshApiRenew SSRF 路径

[`packages/shared/src/sources/credential-manager.ts:980-1001`](packages/shared/src/sources/credential-manager.ts) `refreshApiRenew()` 接受用户在 Source config 写的任意 `renewEndpoint.path`，直接 fetch 后把 token 作为 Authorization header 发出——无 SSRF 防护（私有 IP / 169.254.169.254 AWS 元数据 / localhost / 非 HTTPS 全放行）。

**[`url-safety.ts`](packages/shared/src/utils/url-safety.ts) 是黑名单制**（`javascript:` / `data:` 等），**不防 SSRF**。

**修法**：fetch 前加 `assertPublicHttpsUrl()`。需用户主动安装恶意 source 模板才触发，**不阻塞重打**。

### A 路安全栈合格 ✓

- 加密 AES-256-GCM + PBKDF2 (100k 迭代) + machine UUID v2
- OAuth state CSRF 验证 + PKCE 已落地
- `getApiKey` IPC 返回 mask 字符串（renderer 永远拿不到 raw token）
- console.log token 全仓 0 命中（仅 headless CLI 模式 `CRAFT_SERVER_TOKEN`，桌面用户走不到）
- 用户聊天 atomicWriteFileSync ×11 已落地

### A 路 P2/P3（不阻塞）

- P2 Electron `sandbox: false`（[`window-manager.ts:169`](apps/electron/src/main/window-manager.ts) — M3 加固）
- P2 OAuth client secret 嵌入桌面 binary（上游设计选择，M3 自建 relay 时切 PKCE-only）
- P3 `MAGIC_BYTES = 'CRAFT01\0'` 文件头字面量（用户 `xxd credentials.enc` 能见）
- P3 `CRAFT_SERVER_TOKEN` env 名残留

**风险**：任何 workspace 成员误跑 `bun publish` / `npm publish` 会把 fork 代码推到 npmjs.com **公共 registry**——闭源商业分发的硬约束被破。`@u-agents` scope 在 npm 上是否抢注未知。**这是本次 review 最值得补的项**。

修法：11 个 package.json 加 `"private": true`（5 分钟，需破例改 .json）。

### B-中-高：baileys → libsignal GPLv3 fork license 边界

`@whiskeysockets/baileys@6.17.16` license MIT ✓，但其 `libsignal: github:WhiskeySockets/libsignal-node` 是直 fork github source（不走 npm registry），libsignal 本身 **GPLv3**（Signal 协议官方）。即使 baileys 标 MIT，包内拉 GPL fork 仍可能对最终二进制带来 GPL 传染担忧。

**实际架构**：worker.cjs 是单独 subprocess，进程隔离 → 主进程不引入 GPL 代码。

修法：[LEGAL.md §5](LEGAL.md) 加段说明 baileys/libsignal GPL 边界 + worker 进程隔离。

### B-中：vendor/copilot CLI 第三方 TOS 未声明

`vendor/copilot/<arch>` 是 GitHub Copilot CLI（proprietary + GitHub TOS 双层）。我们 LEGAL.md 未提"使用受 GitHub Copilot Business/Individual 订阅条款约束"。

修法：[LEGAL.md](LEGAL.md) 补一句即可（与已有 vendor/codex Apache-2.0 声明对偶）。

### B-中：`@modelcontextprotocol/sdk` peer `>=1.0.0` 半敞口 range

碰上 SDK 1.x 大版本破坏会爆。修法：peer 改 `^1.x.y` 锁主版本。

### B 路其他全绿 ✓

- bun.lock exact version 锁定 ✓
- 0 postinstall hook ✓
- LICENSE + NOTICE 完整 + 三平台 extraResources 含 ✓
- git tracked 0 真实凭证 ✓
- merge-base = upstream/main `b31904c6` 干净 ✓
