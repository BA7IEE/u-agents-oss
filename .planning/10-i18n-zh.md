> ⚠️ Round 30 RRR 修正：前 28 轮文档记 "~29 处"，实测 `grep -ic "craft"` 命中数为 33（pl 34），总 **232 处** craft 字面量待清洗。差额来自 i18n key 名本身含 craft（如 `menu.aboutCraftAgents` / `menu.craftMenu` / `onboarding.apiSetup.craftAgentsBackend` 等键名也命中）。

**关键约束**：上游 `bun run lint:i18n:parity` 会强制所有非 en locale 的 keys 与 en.json 一致。如果只改 en + zh-Hans 而漏其他 5 个 locale，**CI/lint 会失败**。

> ⚠️ **额外约束（Round 30 RRR）**：i18n **key 名**本身含 `craft`（如 `menu.aboutCraftAgents` / `menu.craftMenu` / `menu.hideCraftAgents` / `menu.quitCraftAgents` / `onboarding.apiSetup.craftAgentsBackend` / `editPopover.example.addSource` 引用 "Craft space" / `onboarding.reauth.loginWithCraft` 等）。**M1 不改 key 名**——只改 value——因为 key 名变更会让所有 i18n 调用方（`i18n.t('menu.aboutCraftAgents')`）必须同步改 → 影响面太大且增加上游同步冲突。M2 评估是否重命名 key（要配套 codemod）。

**M1 处理决策**：
- en + zh-Hans **必须**完整翻译（用户主要语言）
- de/es/ja/hu/pl 至少**保持 parity**（key 数一致）：品牌词清洗时，把 en 新值直接复制到这 5 个 locale 即可——反正 U Agents 用户群基本不用这些语言
- 不删除这 5 个 locale 文件——删除会破坏上游同步（M2 再决定要不要精简到只支持中英文）

**结论**：上游中文化质量不错，**M1 核心工作是品牌词清洗（7 个 locale）+ 加 U-API 相关 keys（7 个 locale 同步加，非中英文用 en 内容占位）**。

## 5. 命名规范与翻译原则

### 5.1 品牌词大小写与连字符

| 写法 | 何时用 | 例 |
|---|---|---|
| `U Agents` | 用户可见的品牌名（含空格，与 LOGO 一致）| 窗口标题、关于页、菜单、Onboarding 文案 |
| `优智体` | 中文环境的桌面应用名 | 同上场景的中文版 |
| `U-Agents` | **文件名 / 工件名**（连字符替代空格，避免文件系统/CLI 引号麻烦）| `U-Agents-arm64.dmg`、`U-Agents-x64.exe` |
| `u-agents` | **代码标识符 / 路径 / NPM scope**（小写连字符）| `@u-agents/shared`、`u-agents-update` bucket、git 仓库目录 |
| `U-API` | 中转服务品牌（连字符固定不变，i18n 中保持英文不译）| 连接卡片、错误提示、设置页 |
| `u-api-default` | LLM 连接的 slug（小写连字符）| `LlmConnection.slug` 字段、provider-metadata key |
| `U Studio` | 公司/运营方名（用户可见、合规署名场景）| About 对话框版权署名、Linux maintainer |
| `u-studio.cn` | 域名 | 所有 URL |

**核心原则**：
- 用户**看见**的所有品牌名都是带空格 / 大写形式（`U Agents` / `U-API` / `U Studio`）
- 用户**看不见**的（文件系统、代码、URL）一律小写连字符（`u-agents` / `u-api-default` / `u-studio.cn`）
- DMG / EXE / AppImage 文件名是个例外（用 `U-Agents`），因为这是用户能在 Finder / Explorer 里看见的文件名，但仍要用连字符避免空格——折中方案。

## 6. 实施流程

### 6.1 M1 阶段（最小化中文化，**7 个 locale 都要碰**）

只做品牌词清洗 + 新增 U-API keys：

1. **品牌词清洗（en + zh-Hans 用户主要语言）**：
   - zh-Hans.json：批量替换 §2.1 表中的字符串
   - zh-Hans.json：替换 §2.2 表中的特殊用法
   - en.json：同步替换品牌词

2. **品牌词清洗（其他 5 个 locale：de/es/ja/hu/pl）**：
   - 这 5 个 locale 把含 "Craft" 的 keys **直接复制 en.json 改后的英文值**（不翻译）
   - 反正 U Agents 用户群不用这些语言；M2 再决定是否精简到只支持中英文

3. **新增 U-API keys（§3 + §4 共约 30 个 key）**：
   - en.json + zh-Hans.json：按 §3 / §4 表填入英文 + 中文
   - de/es/ja/hu/pl：**只复制 en 的英文值**（保持 parity，不翻译）

4. ~~**菜单"重置默认"文案修复**~~ ✅ **已完成**（M1/M2 期间落地，commits `35444566` / `e473971d` / `75bcda89`）：
   - `menu.resetToDefaultsDetail` 已改为 "完全退出应用，删除 `~/.u-agents/` 目录后重新安装"，不再引用上游被剥离的 `bun run fresh-start`
   - 7 个 locale 全部对齐（验证：`grep menu.resetToDefaultsDetail packages/shared/src/i18n/locales/*.json`）

5. **校验**：跑 `bun run lint:i18n:parity` 确认 7 个 locale 都和 en.json 1:1（key 数 + key 名）

6. **目测**：启动应用，看 onboarding / 设置页 / 错误提示是否还有 "Craft" 字样

> **执行 sed 替换 7 个 locale 时**，可以一行命令搞定品牌词替换：
> ```bash
> for f in packages/shared/src/i18n/locales/*.json; do

## 7. 翻译质量自检

每次同步上游后跑：

```bash
# 1. 完整性
bun run lint:i18n:parity
# 应输出 "0 keys missing"

# 2. 品牌污染
grep -nE '"[a-zA-Z_.]+"\s*:\s*"[^"]*Craft[^"]*"' packages/shared/src/i18n/locales/zh-Hans.json
grep -nE '"[a-zA-Z_.]+"\s*:\s*"[^"]*Craft[^"]*"' packages/shared/src/i18n/locales/en.json
# 都应为空（除非上游加了新 key 还没处理）

# 3. 我们新增的 keys 一致性
grep -nE '"uapi\.' packages/shared/src/i18n/locales/zh-Hans.json | wc -l
grep -nE '"uapi\.' packages/shared/src/i18n/locales/en.json | wc -l
# 两个数字应相等
```

如果 §2 之后再做品牌替换，**优先在 en.json 替换**，再翻译到 zh-Hans.json，避免脱钩。
